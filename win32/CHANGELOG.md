## [V0.0.2] 2026-10-15 ~ 2026-10-16

### 新增（回迁 / 32 位专属）
- 目标系统 Windows 7 SP1+：Python 3.8.10 **32 位** + PySide2 5.15.2.1（Qt 5.15.2，
  两者的最后 Win7 支持版本）；一个 32 位产物通吃 Win7 32/64 位系统
- **Win7 专用 UCRT 随包**（`vendor/ucrt-x86/`，41 个 DLL，SDK 不带版本号的
  10.0.10240 版；spec 查找失败直接报错）；产物 PE 审计工具 `tools/audit_dist_win7.py`
  （位数/导入解析/UCRT 血统）；32 位内存实测工具 `tools/mem_probe.py`
- 显示缓冲定档 **5M 默认 / 20M 上限**（32 位 2GB 地址空间实测：512M 档灌到
  310MB 即 MemoryError），并加**内存耗尽自动降档**（上限减半重试，仍失败只丢
  当包并提示，不抛回 Qt 槽）
- 配置文件独立命名 **`pycom32.json`**（与 PyCom 的 pycom.json 同目录共存互不覆盖）
- 数据含 0x00 的 **NUL 防护**：行表统一剥离 U+0000（PySide2 的 drawText 不接受
  内嵌空字符，此前会导致接收视图每帧绘制中断、界面假死、滚轮才恢复）
- 行表跟随缓冲裁剪、独立字体、校验 7 种、多条发送 SSCOM 语义等与主线同步

### 变更
- 打包只出单文件版 `dist\PyCom32.exe`（≈20MB）；spec 关键点：显式带
  `python3.dll`（PyInstaller 5.x 默认不收）、保留 `Qt5Qml.dll`
  （pyside2.abi3.dll 硬链）、剔除 Qt5 未用组件与两个永不加载的备用平台插件
- Qt5 适配：`exec_()`、枚举简写、QActionGroup/QShortcut 回 QtWidgets、高分屏
  属性显式开启（AA_EnableHighDpiScaling 等）、明暗主题走 QSS+调色板+DWM；
  QSS 字体链加入 `"Microsoft YaHei"`（Win7 无 "Microsoft YaHei UI" 字体族，
  原回退 Segoe UI 会让中文走系统回退链，命中微软雅黑后观感统一）
- 串口被占用/断线重连的等待期（黄灯"重连中…"轮询）：打开按钮转**「取消」**，
  点击即中止轮询并完整还原（此前等待无法取消，只能切菜单模式绕开）
- 菜单勾选标记改**条目图标列**（Qt5 QSS 勾选列错位的 workaround；早期方案，
  终版见下：行尾 ●）
- 状态栏改造与主线同步：第 1 框只显示 已连接/未连接，其余提示走第 4 框
  3 秒临时通知并回显常驻连接信息
- 串口接收路径去掉 `waitForReadyRead(0)` 排空（Qt5 每次超时都会给端口置
  TimeoutError 并发 errorOccurred，实测 CH343 一次不落）
- terminal.py 的 ANSI/退格控制字节改显式转义（运行语义不变，防编辑丢字节）
- 新增 Qt5 专属测试：菜单 triggered 槽签名静态守卫、菜单真实触发回归、OOM 降级、
  缓冲 20M 收敛

### 修复
- **UCRT 血统**：开发机 System32/SysWOW64 的 ucrtbase（10.0.26100）依赖 Win8+
  才有的 API-Set，干净 Win7 上程序必挂且开发机测不出——改用 SDK 的
  Redist 版随包（修复前审计 7 项风险 → 0）
- 打包缺 `python3.dll` 启动即 "DLL load failed while importing QtCore"
- `QAction.triggered` 在 PySide2 不传参：带必选参数的 lambda 槽触发即抛
  TypeError 且静默失效（"通讯端口菜单点了没反应"）——改 `_=False` 形态
- Qt5 QSS 定制菜单的勾选项文字错位（indicator 归零 + 早期勾号走图标列，终版行尾 ●）
- `QAction.menu()` 遍历菜单树会因 GC 连带删掉 QMenu（改 findChildren 收集）
- 512M 缓冲档在 32 位下内存耗尽（见上"定档 + 降档"）
- **OOM 降级重试非幂等**（审查 P2-2）：`builder.feed` 抛 MemoryError 降档重试时，
  同一包字节被再次 append 进接收缓冲（*.bin 导出与显示翻倍）——改为追加缓冲与
  喂行表分段重试，append 成功即不重复
- 审计脚本/内存实测工具在中文（GBK）控制台输出 ✓/✗/⚠ 直接
  UnicodeEncodeError 中断（审查 P2-1）——stdout 不可编码字符降级为 ?，
  默认中文终端可跑完两条审计
- 行数硬上限裁剪遵守转存日志游标（同主线，极端突发不丢未写盘行）；日志脱钩
  （正常关闭、打开失败、两种写失败、关窗收尾）统一收敛到 `_detach_rx_log()`
  （内部负责关闭句柄 + 复位游标，幂等），防残留游标把硬上限裁剪永久锁死；
  关窗时写盘失败不再中断退出流程（参数照常落盘）
- OOM 二次失败（feed 仍失败）路径：字节已入缓冲时提示改为"未能显示"且
  RX 计数照常累加，与缓冲/*.bin 实际内容一致（不再误报"丢弃"）
- 菜单勾选标记终版 = **行尾实心圆 `●`**（indicator 归零）：真机 Win7 分数
  缩放（125%/150%）下勾号图形全系列不可用——手绘路径缺笔乱码、✓ 字符位图
  发虚、**系统原生 indicator 勾号也发虚**、垫透明图标对齐还会把弹出菜单高度
  算短（底边被裁）；行首前置标记（几何字符/全角字符）又因 ● 在微软雅黑里
  是窄字符、与全角空格不等宽而无法对齐。定稿 `●` 放**行尾**：条目前缀不动
  （汉字天然对齐），列对齐用 Qt 制表符右对齐机制（`文字\t　●`，快捷键同
  布局），标记与文字间距 ≥ 两空格；`QMenu::item` 右内边距 24→8px 使 ●
  贴近菜单右缘（实测 ● 距右缘 30→14 逻辑像素，文字与标记间距不受影响）；
  含子菜单的菜单（发送/显示）经 QSS 属性选择器恢复 24px 右缓冲——8px 会把
  子菜单条目的 ▶ 箭头压进长文字里。
  标记在菜单弹出前按勾选态刷新（test_menu_text_marker 守卫）

### 测试 / 验证
- **106 项**单测全过（32 位解释器 + offscreen；比主线多 Qt5 专属守卫；
  含日志写失败游标复位/关窗保存回归、占用等待可取消）
- PE 审计（位数/导入解析/UCRT 血统）双通过：「未发现 Win7 兼容性风险项」
- 产物在 Win11 开发机（WoW64）启动冒烟通过；真实 CH343 收流验证正常
- ✅ Win7 真机验收全部通过：64 位（2026-10-16）+ 32 位（2026-10-17），期间
  发现的问题均已修复并复验（[../docs/05-测试与验收.md](../docs/05-测试与验收.md) §7.7）
