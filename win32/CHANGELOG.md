# PyCom32 更新日志（win32 / Win7 32 位分支）

格式参照 Keep a Changelog；版本号单一来源 `app/version.py`（与 win64 主线同步）。
总览见 [../CHANGELOG.md](../CHANGELOG.md)。运行环境：Python 3.8.10（**32 位**，
`D:\Program Files\Python38-x32`）+ PySide2 5.15.2.1 / Qt 5.15.2，目标系统
**Windows 7 SP1+**（32/64 位系统均可）。本分支自主线整树回迁，只同步修复、

## [V0.0.5] 2026-10-24

定版（与主线同步提交）。

- 版本号 V0.0.5（与主线同步）

### 新增
- **固定布局**：按钮类控件位置恒定（对齐启动时"图中所示"布局，末拍沉降
  钉死自然宽）——窗口收缩时不再压缩/移位，超出部分被窗口右缘裁剪；
  拉伸时右侧按钮组贴右缘、中缝留空；显示框/发送内容框跟随窗口伸缩
  （与主线同步）

  右侧弹出独立小窗（紧贴右缘，随主窗移动/缩放跟随贴边），显示框与主
  界面布局完全不受影响（与主线同步）
- **文件块再右移一个英文字符宽**；**窄窗时状态栏版本号隐藏**（展宽恢复，
  版本随时可在"关于"查看；与主线同步）

### 修复
- **扩展小窗贴屏定位**：主窗右缘贴屏（如最大化）时，小窗自动改贴主窗
  左缘或夹回屏幕内，不再整个落到屏幕外（二十四轮 F1，与主线同步）
- **扩展小窗随主窗缩放跟随**：此前仅移动跟随（moveEvent），拖右/下缘改变
  尺寸时不重贴边、高度不同高——现缩放时同步重设位置与高度，且贴边 y 向
  上下双侧夹取（二十八轮 F1/F2，与主线同步）
- **主窗最小化时扩展小窗随之隐藏**，恢复时按扩展按钮状态重新显示并贴边
  （二十八轮 F3，与主线同步）
- 扩展小窗标题更正为「**PyCom32 扩展**」（此前误写 PyCom）；恢复瞬间
  贴边延后一拍，规避最小化期伪几何（二十九轮）
- 点"扩展"改为**先定几何、置深色、再显示**（不再闪现旧位置/浅色标题栏

  开销）；读不回（拖动+关闭+重开后原生窗重建期）退回无条件设置；设置

  一对 `WM_NCACTIVATE` 翻转（后台窗重绘会被 DWM 惰性化、非确定性滞后一
  拍）——此前只设属性不重绘，深色下标题栏长时间白色（与主线同步）
- **打包恢复双产物**（2026-10-24 用户指令，与主线同步）：单文件版之外
  同时产出**目录版**（`dist/PyCom32/`，免解压——启动零解包，整文件夹
  拷贝使用）；同日第二轮指令：**PyInstaller 5.13.2→6.22.2 升级与主线
  同版**，目录版结构对齐主线（exe + `_internal/`，DLL 与 Win7 专用 UCRT
  全在 `_internal/` 内；官方支持面 Win8+，引导仍按 Win7 特性级编译，
  **Win7 32 位真机启动复验通过**）；审计随布局升级为三条（单文件/目录版/
  UCRT 输入），全过；全量回归 136 项全过

## [V0.0.4] 2026-10-22

### 新增（与主线同步 / 本分支相关）
- **SSCOM 式缩窗截断**（替代整列隐藏）：窗口缩窄时，工具行右区（打开文件/
  路径框/发送文件/停止/清发送区/收起/最前/保存参数/扩展）与右侧选项两列
  （HEX显示/保存数据/加时间戳…/HEX发送/加校验…）保持各自自然宽度、整体向右
  溢出被窗口边缘直接裁掉（与原版窄窗截图一致）；清除窗口/查找/新窗口/自动滚屏
  与左下角串口配置列钉住自然宽度**永不压缩**，窗口最窄 330px。
  实现：新增 `ClipBox` 容器（`minimumSizeHint()==(0,0)`，内容溢出交父级裁剪）
  包住工具行右区与选项两列；启动后 0/300/1000/2500ms 四拍把上述固定控件钉在
  `sizeHint` 宽度（字体度量沉降后收敛）；`_apply_narrow` 只保留扩展面板收起、
  查找条隐藏、状态栏连接信息让位三件无法截断的事
- **小工具菜单重排**：扩展页直达（**进制转换**（原"转换计算器"更名，
  扩展区页签同步更名）/ ASCII码表 / 多条字符串发送）为一组，
  计算器 / 设备管理器 / 文件资源管理器为一组
- 工具行新增**"新窗口"按钮**（清除窗口 → 查找 → 新窗口）：单击即再启动一个独立的应用实例
  （`QProcess.startDetached` 独立进程；两实例配置同源，但同一串口/端口资源
  由系统互斥——两边同时打开同一串口会走占用提示）
- 小工具菜单新增**文件资源管理器**（默认定位"此电脑"）与扩展页直达入口
  **转换计算器 / ASCII码表**（点击自动展开扩展面板并切到对应页签）
- 工具行文件块（打开文件/路径/发送文件/停止/清发送区）起始横坐标恒定与左下角
  "发送"按钮右缘对齐（垫片由渲染坐标实测：发送右缘 − 自动滚屏右缘 − 两处行距）
- 版本号升 **V0.0.4**（与主线同步）

### 修复
- **状态栏"本机IP"不再显示未使用的地址**（二十一轮 F4，与主线同步）：TCP

### 测试

## [V0.0.3] 2026-10-17 ~ 2026-10-20

### 新增（与主线同步 / 本分支相关）
- **接收区鼠标选择复制**：拖选正文 → Ctrl+C / Ctrl+Insert / 右键「复制所选」
  复制；跨行选区按逻辑行拼接；拖到上下边缘自动滚屏；终端仿真开启时 Ctrl+C
  优先复制不再发送 0x03
- **复制/保存含时间戳和收发标记**（接收区右键两项独立开关，默认勾选、勾选态 =
  行尾 ●）：关闭后复制与「保存数据」只出正文；开启时行首 `[时间戳]收←◆`
  随行带出；与"加时间戳和分包显示"独立；随 `pycom32.json` 持久化
- **网络 IPv4/IPv6 纯单栈**：本地 IP 下拉列出 0.0.0.0（仅 IPv4 全部）+ 各
  IPv4 + ::（仅 IPv6 全部）+ 各 IPv6（fe80::x%作用域 可直接用），选中哪个
  地址就只绑定/收发该族、两族互不混收；远程地址支持 IPv6 字面量、`[::1]`
  自动剥方括号（主机名仅 TCP 客户端，UDP 只认地址字面量）；UDP 发送失败报
  一次可恢复提示。不做双栈（默认值零变化）
- 帮助菜单新增**检查更新…**：浏览器打开仓库 Releases 页，发布与下载在网页
  进行；应用内不联网、不做自动下载
- 转换计算器新增 **HEX 小端 LE / HEX 大端 BE** 字段（与主线同步）
- 转换计算器底部新增**只读"C语言数组"框**（与主线同步，2026-10-20 用户要求）：
  随值联动，按小端内存序展开为 `0xBC, 0x9A, …` 字面量，不可输入/删除、只可
  选择复制，供固件代码直接粘贴

### 变更
- **网络模式锁死无关输入框**：TCP 客户端锁「本机端口」、TCP 服务器锁
  「远程 IP/端口」（置灰 + 悬停显示"无需配置"原因），UDP 四项全有效；锁死只禁
  输入，值仍随配置持久化
- **显示缓冲上限档位调整**：删除 200K 档；上限放宽 20M → **50M**（历史实测
  128M/256M 档正常、512M 档才 OOM，50M 远离风险线且内存耗尽自动降档兜底）；
  删除档位的老配置收敛到最小档 500K，默认值不变（5M）
- 版本号升 **V0.0.3**（与主线同步）

### 修复（与主线同步 / 本分支相关）
- **启动期串口枚举去重 + 显式 `upx=False`**（与主线同步）：删除 `_startup` 里的
  第二次串口枚举；spec 显式 `upx=False`（UPX 壳拖慢启动且提高杀软误报率）。
  启动慢的主体是单文件版每次解包 48 MB + 杀软实时扫描（量化基线见 docs/03）
- **TCP 客户端"本机 IP"真实生效**（十九轮 F1，历史遗留，与主线同步；二十轮 F1
  收口绑定范围）：`TcpClientLink` 此前从不绑定本地地址——下拉可选、状态栏照
  显示，实际完全被忽略。现在选了**具体网卡地址**才预绑定（限定源地址/出口网卡）；
  "全部"档（0.0.0.0/::）、回环与未配置一律不绑——源与协议族交回 Qt 由目标地址
  决定，主机名保留 v4/v6 多地址回退（默认 127.0.0.1 预绑定会钉死源，连局域网
  设备直接报 Network unreachable）；绑定失败立即报"本机IP绑定失败"。
  出厂默认 local_ip 同步从 127.0.0.1 改为 0.0.0.0
- **拖动滚动条松手时不在底部才取消自动滚屏勾选**（十九轮 F2，与主线同步）：
  拖到底追最新数据不再被取消勾选
- **状态栏收发速率实时显示**（与主线同步）：旧实现收/发路径每收一包就用
  "RX: 总量"覆盖状态栏、把速率后缀抹掉（RX 持续接收下永远看不到速率、TX 只在
  发送间隙偶尔可见），且速率每秒清零一拍归零——现在收/发只累计数，速率与总量
  统一由定时器渲染（**250ms 刷新**，最近 1 秒滑窗增量：突发后保持满一秒才归零）
- **多条发送表格深色适配**（用户反馈有字符串行时出现白块）：Qt5 原生样式
  （windowsvista）画"点击发送"按钮与 HEX 勾选框不吃深色调色板（按钮浅灰、
  未勾选指示器白块）、表头角落按钮白块——深色下改按主题 QSS 同源颜色手绘
  按钮/勾选框（勾选画对勾），角落按钮由 QSS 显式着色；浅色仍走原生观感不变
- **自动滚屏跟随用户回看**（2026-10-20 定稿交互，与主线同步）：滚轮上翻、拖拽
  选择、拖动滚动条上行 → **"自动滚屏"勾选自动取消**（视图停住，持续接收下可安心
  选择复制，勾选状态与实际跟随一致）；**再次勾选立即跳回最底部**，不需要等新数据
  到达
- **定时发送最小间隔 10ms → 1ms**（实际精度受 Windows 系统定时器粒度限制）
- **扩展区深色模式适配**：真机原生样式下页签页（QTabWidget::pane）不被应用
  调色板影响、回退白色——显式样式化 pane 背景为主题底色；ASCII 码表末列
  撑满不留原生白底；深色调色板补 Disabled 组的 Window 色（模态对话框打开时
  主窗口被禁用部分不再回白）
- **折行行的鼠标选择/复制取到错误文本**（十四轮 X1）：命中映射与绘制几何
  同源（折行段计入列、行号按实际视觉行回推），折行段不再与后续行叠画
- **对话框标题栏跟随深色**：主线靠 Qt6.5+ setColorScheme 自动跟随，Qt5 缺失
  该 API——应用级**单例**事件过滤器（弱引用当前主窗口）对顶层对话框
  （QMessageBox/QInputDialog/QFileDialog）的 Show 统一做 DWM 置暗；
  Win10 1809+ 生效，Win7 无此 DWM 属性自动忽略（标题栏保持系统浅色，属系统
  限制）。必须单例：QApplication 的过滤器列表会强持过滤器对象的 Python 包装，
  每窗口自装会让旧窗口永不释放、事件分派随窗口数 O(N²)（实测全量跑拖慢 10 倍）
- **UDP 发送失败提示三处收尾**（十六轮 F1/F2/F3）：主机名措辞限定 TCP 客户端
  （UDP 只认地址字面量）；发送失败时链路仍绑定，界面保持「已连接/关闭」只亮
  ERR 灯；链路已上报具体原因时 `_write` 不再叠加通用提示
- 时间戳前缀改为**随行记录**（与"加时间戳和分包显示"勾选解耦）

### 测试 / 验证
- **132 项**单测全过（32 位解释器 + offscreen；比主线多 Qt5 专属守卫；
  含上述各功能的回归、对话框标题栏置暗路由与多条发送表格深色手绘像素断言；
  剪贴板断言改桩对象——系统剪贴板可能被其他进程长期占用）
- PE 审计（位数/导入解析/UCRT 血统）双通过：「未发现 Win7 兼容性风险项」


## [V0.0.2] 2026-10-15 ~ 2026-10-16

### 新增（回迁 / 32 位专属）
- 目标系统 Windows 7 SP1+：Python 3.8.10 **32 位** + PySide2 5.15.2.1（Qt 5.15.2，
  两者的最后 Win7 支持版本）；一个 32 位产物通吃 Win7 32/64 位系统
- **Win7 专用 UCRT 随包**（`vendor/ucrt-x86/`，41 个 DLL，SDK 不带版本号的
  10.0.10240 版；spec 查找失败直接报错）；产物 PE 审计工具 `tools/audit_dist_win7.py`
  （位数/导入解析/UCRT 血统）；32 位内存实测工具 `tools/mem_probe.py`
- 显示缓冲定档 **5M 默认 / 20M 上限**（32 位 2GB 地址空间实测：512M 档灌到
  310MB 即 MemoryError），并加**内存耗尽自动降档**（上限减半重试，仍失败只丢
  当包并提示，不抛回 Qt 槽）
- 配置文件独立命名 **`pycom32.json`**（与 PyCom 的 pycom.json 同目录共存互不覆盖）
- 数据含 0x00 的 **NUL 防护**：行表统一剥离 U+0000（PySide2 的 drawText 不接受
  内嵌空字符，此前会导致接收视图每帧绘制中断、界面假死、滚轮才恢复）
- 行表跟随缓冲裁剪、独立字体、校验 7 种、多条发送 SSCOM 语义等与主线同步

### 变更
- 打包只出单文件版 `dist\PyCom32.exe`（≈20MB）；spec 关键点：显式带
  `python3.dll`（PyInstaller 5.x 默认不收）、保留 `Qt5Qml.dll`
  （pyside2.abi3.dll 硬链）、剔除 Qt5 未用组件与两个永不加载的备用平台插件
- Qt5 适配：`exec_()`、枚举简写、QActionGroup/QShortcut 回 QtWidgets、高分屏
  属性显式开启（AA_EnableHighDpiScaling 等）、明暗主题走 QSS+调色板+DWM；
  QSS 字体链加入 `"Microsoft YaHei"`（Win7 无 "Microsoft YaHei UI" 字体族，
  原回退 Segoe UI 会让中文走系统回退链，命中微软雅黑后观感统一）
- 串口被占用/断线重连的等待期（黄灯"重连中…"轮询）：打开按钮转**「取消」**，
  点击即中止轮询并完整还原（此前等待无法取消，只能切菜单模式绕开）
- 菜单勾选标记改**条目图标列**（Qt5 QSS 勾选列错位的 workaround；早期方案，
  终版见下：行尾 ●）
- 状态栏改造与主线同步：第 1 框只显示 已连接/未连接，其余提示走第 4 框
  3 秒临时通知并回显常驻连接信息
- 串口接收路径去掉 `waitForReadyRead(0)` 排空（Qt5 每次超时都会给端口置
  TimeoutError 并发 errorOccurred，实测 CH343 一次不落）
- terminal.py 的 ANSI/退格控制字节改显式转义（运行语义不变，防编辑丢字节）
- 新增 Qt5 专属测试：菜单 triggered 槽签名静态守卫、菜单真实触发回归、OOM 降级、
  缓冲 20M 收敛

### 修复
- **UCRT 血统**：开发机 System32/SysWOW64 的 ucrtbase（10.0.26100）依赖 Win8+
  才有的 API-Set，干净 Win7 上程序必挂且开发机测不出——改用 SDK 的
  Redist 版随包（修复前审计 7 项风险 → 0）
- 打包缺 `python3.dll` 启动即 "DLL load failed while importing QtCore"
- `QAction.triggered` 在 PySide2 不传参：带必选参数的 lambda 槽触发即抛
  TypeError 且静默失效（"通讯端口菜单点了没反应"）——改 `_=False` 形态
- Qt5 QSS 定制菜单的勾选项文字错位（indicator 归零 + 早期勾号走图标列，终版行尾 ●）
- `QAction.menu()` 遍历菜单树会因 GC 连带删掉 QMenu（改 findChildren 收集）
- 512M 缓冲档在 32 位下内存耗尽（见上"定档 + 降档"）
- **OOM 降级重试非幂等**（审查 P2-2）：`builder.feed` 抛 MemoryError 降档重试时，
  同一包字节被再次 append 进接收缓冲（*.bin 导出与显示翻倍）——改为追加缓冲与
  喂行表分段重试，append 成功即不重复
- 审计脚本/内存实测工具在中文（GBK）控制台输出 ✓/✗/⚠ 直接
  UnicodeEncodeError 中断（审查 P2-1）——stdout 不可编码字符降级为 ?，
  默认中文终端可跑完两条审计
- 行数硬上限裁剪遵守转存日志游标（同主线，极端突发不丢未写盘行）；日志脱钩
  （正常关闭、打开失败、两种写失败、关窗收尾）统一收敛到 `_detach_rx_log()`
  （内部负责关闭句柄 + 复位游标，幂等），防残留游标把硬上限裁剪永久锁死；
  关窗时写盘失败不再中断退出流程（参数照常落盘）
- OOM 二次失败（feed 仍失败）路径：字节已入缓冲时提示改为"未能显示"且
  RX 计数照常累加，与缓冲/*.bin 实际内容一致（不再误报"丢弃"）
- 菜单勾选标记终版 = **行尾实心圆 `●`**（indicator 归零）：真机 Win7 分数
  缩放（125%/150%）下勾号图形全系列不可用——手绘路径缺笔乱码、✓ 字符位图
  发虚、**系统原生 indicator 勾号也发虚**、垫透明图标对齐还会把弹出菜单高度
  算短（底边被裁）；行首前置标记（几何字符/全角字符）又因 ● 在微软雅黑里
  是窄字符、与全角空格不等宽而无法对齐。定稿 `●` 放**行尾**：条目前缀不动
  （汉字天然对齐），列对齐用 Qt 制表符右对齐机制（`文字\t　●`，快捷键同
  布局），标记与文字间距 ≥ 两空格；`QMenu::item` 右内边距 24→8px 使 ●
  贴近菜单右缘（实测 ● 距右缘 30→14 逻辑像素，文字与标记间距不受影响）；
  含子菜单的菜单（发送/显示）经 QSS 属性选择器恢复 24px 右缓冲——8px 会把
  子菜单条目的 ▶ 箭头压进长文字里。
  标记在菜单弹出前按勾选态刷新（test_menu_text_marker 守卫）
