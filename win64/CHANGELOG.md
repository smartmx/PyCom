# PyCom 更新日志（win64 主线）

格式参照 Keep a Changelog；版本号单一来源 `app/version.py`（与 win32 分支同步）。
总览见 [../CHANGELOG.md](../CHANGELOG.md)。运行环境：Python 3.13（64 位）+
PySide6 / Qt6，目标系统 Windows 10+。

## [V0.0.4] 2026-10-22

### 新增
- **SSCOM 式缩窗截断**（替代整列隐藏）：窗口缩窄时，工具行右区（打开文件/
  路径框/发送文件/停止/清发送区/收起/最前/保存参数/扩展）与右侧选项两列
  （HEX显示/保存数据/加时间戳…/HEX发送/加校验…）保持各自自然宽度、整体向右
  溢出被窗口边缘直接裁掉（与原版窄窗截图一致）；清除窗口/查找/新窗口/自动滚屏
  与左下角串口配置列钉住自然宽度**永不压缩**，窗口最窄 330px。
  实现：新增 `ClipBox` 容器（`minimumSizeHint()==(0,0)`，内容溢出交父级裁剪）
  包住工具行右区与选项两列；启动后 0/300/1000/2500ms 四拍把上述固定控件钉在
  `sizeHint` 宽度（字体度量沉降后收敛）；`_apply_narrow` 只保留扩展面板收起、
  查找条隐藏、状态栏连接信息让位三件无法截断的事
- **小工具菜单重排**：扩展页直达（**进制转换**（原"转换计算器"更名，
  扩展区页签同步更名）/ ASCII码表 / 多条字符串发送）为一组，
  计算器 / 设备管理器 / 文件资源管理器为一组
- 工具行新增**"新窗口"按钮**（清除窗口 → 查找 → 新窗口）：单击即再启动一个
  独立的应用实例（`QProcess.startDetached` 独立进程；两实例配置同源，但同一
  串口/端口资源由系统互斥——两边同时打开同一串口会走占用提示）
- 小工具菜单新增**文件资源管理器**（默认定位"此电脑"）与扩展页直达入口
  **转换计算器 / ASCII码表**（点击自动展开扩展面板并切到对应页签）
- 工具行文件块（打开文件/路径/发送文件/停止/清发送区）起始横坐标恒定与左下角
  "发送"按钮右缘对齐（垫片由渲染坐标实测：发送右缘 − 自动滚屏右缘 − 两处行距）
- 版本号升 **V0.0.4**（`app/version.py` 单一来源）

### 修复
- **状态栏"本机IP"不再显示未使用的地址**（二十一轮 F4）：TCP 客户端不预绑定
  的档位（"全部"0.0.0.0/::、回环、未配置）由原样显示所选地址改为
  「本机IP=自动（随目标）」——与实际源地址来源一致；选具体网卡地址时照常
  显示该地址（绑定决策收口为 `_bindable_local()` 单一判据，open() 与
  describe() 同源）

### 测试
- **125 项**单测全过（新增 新窗口按钮启动实例、小工具菜单三入口、窄窗截断
  （右侧不隐藏、左块不压缩）与文件行对齐算式；含 V0.0.3 全部回归）

## [V0.0.3] 2026-10-17 ~ 2026-10-20

### 新增
- **接收区鼠标选择复制**：拖选正文 → Ctrl+C / Ctrl+Insert / 右键「复制所选」
  复制；跨行选区按逻辑行拼接；拖到接收区上下边缘自动滚屏可跨屏选择（16ms
  细分 + 亚像素累积，滚动顺滑）；终端仿真开启时 Ctrl+C 优先复制不再发送 0x03
- **复制/保存含时间戳和收发标记**（接收区右键两项独立开关，默认勾选、勾选态 =
  行尾 ●）：关闭后「复制所选/复制全部文本」与「保存数据」只出正文；开启时行首
  `[时间戳]收←◆` 随行带出（选区按行首列 0 起选才带注记，半途起选不带）。
  与"加时间戳和分包显示"**独立**；随 `pycom.json` 持久化
- **网络 IPv4/IPv6 纯单栈**：本地 IP 下拉列出 0.0.0.0（仅 IPv4 全部）+ 各
  IPv4 + ::（仅 IPv6 全部）+ 各 IPv6（链路本地 fe80::x%作用域 可直接用），
  选中哪个地址就只绑定/收发该族、两族互不混收（绑 :: 时 IPv4 客户端连不上）；
  远程地址支持 IPv6 字面量、`[::1]` 自动剥方括号（主机名仅 TCP 客户端，UDP
  只认地址字面量）；UDP 远程地址无法解析/发送失败报一次状态栏提示（链路保持
  绑定、界面保持已连接）、恢复后回正常。不做双栈（默认值零变化）
- 转换计算器新增 **HEX 小端 LE / HEX 大端 BE** 字段：字节序互转
  （空格分隔字节串可双向输入）
- 转换计算器底部新增**只读"C语言数组"框**（2026-10-20 用户要求）：随值联动，
  按小端内存序展开为 `0xBC, 0x9A, …` 字面量（如 HEX 输入 `12 34 56 78 9A BC`），
  不可输入/删除、只可选择复制，供固件代码直接粘贴
- 帮助菜单新增**检查更新…**：用默认浏览器打开仓库 Releases 页
  （`github.com/smartmx/PyCom/releases/latest`），最新版发布与下载在网页进行
  （两产物同一仓库发布）；应用内不联网、不做自动下载

### 变更
- **网络模式锁死无关输入框**：TCP 客户端锁「本机端口」、TCP 服务器锁
  「远程 IP/端口」（置灰 + 悬停显示"无需配置"原因），UDP 四项全有效；锁死只禁
  输入，值仍随配置持久化
- **显示缓冲上限档位调整**：删除 200K 档；上限放宽到 **100M**（原 50M）；
  删除档位的老配置收敛到最小档 500K，默认值不变（10M）
- 版本号升 **V0.0.3**（app/version.py 单一来源）

### 修复
- **启动期串口枚举去重 + 显式 `upx=False`**（启动性能分析_20261021）：`_startup`
  里的第二次串口枚举删除（`_apply_settings` 已枚举过，慢驱动机器上一次枚举可达
  数秒）；spec 显式 `upx=False`——UPX 壳拖慢启动并提高杀软误报率，不再隐式依赖
  "打包机恰好没装 UPX"。启动慢的主体是单文件版每次解包 54 MB + 杀软实时扫描
  （量化基线见 docs/03：无杀软+SSD 下限约 2 s）
- **TCP 客户端"本机 IP"真实生效**（十九轮 F1，历史遗留；二十轮 F1 收口绑定范围）：
  `TcpClientLink` 此前从不绑定本地地址——下拉可选、状态栏照显示、文档称三模式
  共用，实际完全被忽略（多网卡机器以为指定了出口网卡，实际走系统默认源地址）。
  现在选了**具体网卡地址**才预绑定（限定源地址/出口网卡）；"全部"档（0.0.0.0/::）、
  回环与未配置一律不绑——源与协议族交回 Qt 由目标地址决定，主机名保留 v4/v6
  多地址回退（出厂默认 127.0.0.1 预绑定会钉死源，连局域网设备直接报
  Network unreachable）；绑定失败（如本机不存在的地址）立即报"本机IP绑定失败"。
  出厂默认 local_ip 同步从 127.0.0.1 改为 0.0.0.0
- **拖动滚动条松手时不在底部才取消自动滚屏勾选**（十九轮 F2）：此前拖动过程
  不分方向一律取消（拖到底追最新数据也会被取消）——现在松手在底部=回到底部
  跟随、勾选保持，松手不在底部=回看、勾选取消
- **状态栏收发速率实时显示**：旧实现收/发路径每收一包就用"RX: 总量"覆盖状态栏、
  把速率后缀抹掉（RX 在持续接收下永远看不到速率、TX 只在两次发送间隙偶尔可见），
  且速率每秒清零一拍归零——现在收/发只累计数，速率与总量统一由定时器渲染
  （**250ms 刷新**，速率取最近 1 秒滑窗增量：突发后保持满一秒才衰减归零）
- **自动滚屏跟随用户回看**（2026-10-20 定稿交互）：滚轮上翻、拖拽选择、拖动滚动条
  上行 → **"自动滚屏"勾选自动取消**（视图停住，持续接收下可安心选择复制，勾选状态
  与实际跟随一致）；**再次勾选立即跳回最底部**，不需要等新数据到达
- **定时发送最小间隔 10ms → 1ms**（实际精度仍受 Windows 系统定时器粒度限制）
- **扩展区深色模式适配**：真机原生样式下页签页（QTabWidget::pane）不被应用
  调色板影响、回退白色——显式样式化 pane 背景为主题底色；ASCII 码表末列
  撑满不留原生白底；深色调色板补 Disabled 组的 Window 色（模态对话框打开时
  主窗口被禁用部分不再回白）
- **折行行的鼠标选择/复制取到错误文本**（十四轮 X1）：命中映射未计入折行段
  偏移与上方行占用的视觉行数——`_pos_to_point` 改为与绘制完全同源（列补
  `段号×每段列数`、行号按实际视觉行回推），绘制侧折行段占满本行视觉行后
  下一行才接着排（不再与后续行叠画）；选区高亮/注记随之恢复一致
- **UDP 发送失败提示的三处收尾**（十六轮 F1/F2/F3）：①主机名只有 TCP 客户端
  支持（`connectToHost` 走 DNS），UDP 只认地址字面量——tooltip 与文档措辞
  已限定；②发送失败时链路仍绑定可收发，界面不再退化成「未连接/打开」
  （按钮动作与真实动作相反），改为保持「已连接/关闭」只亮 ERR 灯；③链路已
  上报具体原因（如"远程IP无法解析"）时，主窗口 `_write` 不再叠加通用
  "写入失败或对端未就绪"提示覆盖第 4 格
- 时间戳前缀改为**随行记录**（与"加时间戳和分包显示"勾选解耦）：该勾选只决定
  显示与转存是否带出；复制/保存选项、切换勾选后回溯已收内容都能拿到真前缀

### 测试
- 99 → **124 项**全过（新增 鼠标选择复制/自动滚屏、复制与保存注记选项与配置
  往返、折行命中映射、网络 IPv6 单栈回环与远程写法宽容、UDP 发送失败状态
  呈现、检查更新菜单、回看自动取消滚屏勾选/重勾立即跳底、定时发送
  最小 1ms；剪贴板断言改桩对象——系统剪贴板可能被其他进程长期占用；
  多条发送循环测试改"等前两发到达"、终端焦点断言改窗口内焦点，消除全量跑在
  活跃桌面/高负载下的时序抖动）


## [V0.0.2] 2026-10-15 ~ 2026-10-16

### 新增
- **行表跟随缓冲裁剪**：显示缓冲上限同时决定回看深度与 `*.bin` 导出范围
  （裁剪粒度=包，日志游标保护未落盘行；行表另有 50 万行硬上限），不再出现
  "屏幕上有、导出没有"
- 发送区/接收区**独立字体**设置（family/size/bold/underline/color），接收视图
  双字体逐行渲染；时间戳颜色可调
- 校验算法扩到 **7 种**（无/ModbusCRC16/CCITT_CRC16/CRC8/ADD8/ADD16/XOR8），
  末尾 1~4 字节视为帧尾插在前/末尾追加（旧版保留档），第 N 字节起算
- 多条发送对齐 SSCOM 语义：发送按钮列单击发送、双击改注释，顺序号 0=跳过，
  循环按序逐条独立延时
- "小工具"菜单：设备管理器入口；多条发送页签内"导入sscom.ini配置"
- 方向标识规则定稿：收←◆/发→◇ 仅在勾选"加时间戳和分包显示"时显示且仅包首行
- 数据含 0x00 的 **NUL 防护**：行表统一剥离 U+0000（防 PySide2 系 drawText
  假死问题的同源防护，Qt6 下无害）

### 变更
- **状态栏**：第 1 框只显示 已连接/未连接；其余一切提示改为第 4 框临时通知
  （3 秒内新通知刷新，超时回显串口/TCP/UDP 常驻连接信息）
- 编码选择改为菜单栏"编码"菜单（12 预置互斥 + "自定义编码…"对话框），
  收/发/终端按键/日志统一入口 `_current_encoding()`
- 接收转存改为 txt（显示内容，`PyCom-Log-YYYYMMDD_HHMMSS.txt`，勾选即存、
  100ms 增量落盘、清屏经 `cleared` 信号复位游标）
- 串口接收路径去掉 `waitForReadyRead(0)` 排空（Qt5 下每次超时都会污染端口
  错误状态；Qt6 无害，两分支同实现便于同步）
- 打包：只出单文件版 `dist\PyCom.exe`（目录版废弃）；spec 裁剪未用 Qt 组件 +
  TLS/UCRT，单文件 49.7MB → **24.2MB**
- 状态栏样式定稿：五段 QFrame 凹陷分格（sbSeg QSS），第 1 框定宽 75px；
  无 CTS/DSR 段
- 移除主题里无人消费的 `hl_fg` 高亮前景键（高亮只着背景，与既有观感一致）
- QSS 字体链加入 `"Microsoft YaHei"`（Win7 无 "Microsoft YaHei UI" 字体族，
  原回退 Segoe UI 会让中文走系统回退链；Win10/11 仍首选 UI 版，观感不变）
- 网络三模式面板定稿：远程行 → 连接/断开 → 网卡选择（联动本地 IP、悬停全名）
  → 本地行；窄窗模式（<620px）隐藏右侧与查找条
- "启动立刻打开串口"为菜单选项，默认关（open_on_start 持久化）；改波特率自动
  重开串口（CH34x 动态 setBaudRate 不可靠）

### 修复
- 串口被占用/断线重连的等待期（黄灯"重连中…"轮询）：打开按钮转**「取消」**，
  点击即中止轮询并完整还原（此前等待无法取消，只能切菜单模式绕开）
- 分包显示失效：包尾换行留下的空游标会吞掉下一包首行的时间戳前缀
  （表现为此前"加时间戳和分包显示"整体无效）
- 窗口几何越界：配置宽高钳制到屏幕可用区域，外框修正在 showEvent 后做
- 接收区搜索绝对行号/输入防抖/失效重算；积压上限；自动滚屏开关
- 循环发送自停同步取消勾选；保存参数不再打断循环
- 行数硬上限（50 万行）裁剪遵守转存日志游标：极端突发下宁可暂时超上限，
  也不裁掉尚未写盘的行（`display.set_log_keep`）；日志脱钩（正常关闭、打开
  失败、两种写失败、关窗收尾）统一收敛到 `_detach_rx_log()`（内部负责关闭
  句柄 + 复位游标，幂等），基址已越过的残留游标由裁剪兜底自动失效（防硬上限
  被永久锁死）；关窗时写盘失败不再中断退出流程（参数照常落盘）

### 测试
- 92 → **99 项**全过（新增 NUL 剥离、状态栏通知回显、硬上限裁剪游标与残留
  游标兜底、日志写失败游标复位/关窗保存回归、占用等待可取消）

## [V0.0.1] 2026-10-14

首个完整版本：串口（全参数/DTR/RTS/热插拔检测）+ TCP 客户端/服务端（多客户端）/
UDP、HEX/ASCII 显示、时间戳分包、状态栏 TX/RX 计数、多条发送、校验追加、
发送文件（256B 分块 + 连续/1/10/50/100ms 五档）、终端仿真（两方式互斥、
回车补 0A）、转换计算器、原版 sscom51.ini 导入、接收区搜索高亮着色、
断线自动重连、深色模式；pytest 单测 + PyInstaller 打包；界面布局按逆向出的
原版 SSCOM 5.13.1 规格对齐（并排比对通过）。
