## 2. 怎么跑

```bash
# win64（在 win64/ 目录下）
python -m pytest tests/

# win32（在 win32/ 目录下；解释器必须写全路径）
"D:\Program Files\Python38-x32\python.exe" -m pytest tests/
```

- GUI 逻辑用例在无显示环境跑时设 `QT_QPA_PLATFORM=offscreen`；
- **离屏平台无字体**，界面观感类验证（字体渲染、菜单勾号观感、布局目检）必须在
  真实平台跑源码看，offscreen 只能验证逻辑与信号；
- 测试文件头部带 `QTest.qWait` 垫片（PySide2 无该静态方法），两版本通用。

**win32 专属**：菜单 triggered 槽签名静态守卫（扫全 `app/`）、四种模式菜单

### 7.0 前置

| 项 | 要求 |
|---|---|
| 目标机 | Windows 7 **SP1**（32/64 位均可，产物是 32 位 exe）；无 SP1 的 Win7 不支持 |
| 产物 | `dist\PyCom32.exe` —— 单文件便携版，拷单个 exe 过去即可（**无需装 Python**；启动慢几秒属正常） |

### 7.1 启动与界面目检

- [ ] 双击 `PyCom32.exe`，主窗口标题 `PyCom32 串口/网络数据调试器`，无缺 DLL 报错框
- [ ] “通讯端口”菜单四项（串口/TCP客户端/TCP服务端/UDP）都能切换，左侧配置区跟着换
      （这里曾是“点了没反应”的坑位）
- [ ] “显示 → 显示缓冲上限”各档即时生效（状态栏出现“显示缓冲上限: N 字节”），
      **最大档是 50M**（没有 100M/128M/512M，那是主线档位），配置清空后默认选中 5M
- [ ] “显示 → 深色模式”勾选后整体转深色，勾选项**行尾**出现**实心圆 `●`**
      （右对齐成列，与文字间距 ≥ 两空格；该版本不画勾号图形——真机分数
      缩放下一切勾号位图发虚/裁剪）；条目文字前缀不动、整列左对齐；
      **扩展区三页**（多条发送/转换计算器/ASCII 码表）背景同步深色不回白；
      **对话框标题栏**（关于/帮助/自定义编码）在 Win10 1809+ 同步深色
      （Win7 系统不支持 DWM 置暗属性，标题栏保持系统浅色属正常）
- [ ] “编码”菜单切换后收发编码跟着变（发一段中文验证）
- [ ] 窗口向左缩到最窄（约 340px）：右侧发送/选项区隐藏，拉宽恢复
- [ ] 状态栏五段正常：连接状态(已连接/未连接) │ TX 速率 │ RX 速率 │ 连接信息/通知 │ 版本；
      断开串口再重连，第 4 框应短暂显示提示后回显串口参数（3 秒临时通知机制）
- [ ] 已知且**不算 bug**：Win7 下深色模式只影响窗口内部，标题栏仍是系统样式
- [ ] **中文字体目检**：主界面/菜单/按钮的中文字体应统一（**已预防**：QSS 字体链

### 7.2 串口回环

1. 杜邦线短接 USB-TTL 模块的 TX 与 RX，插到 Win7 机器
2. “刷新”后端口下拉应出现该 COM 口（热插拔后再刷新应更新）
3. 打开串口：状态栏“已连接”、指示灯变绿
4. 发 `hello` → 接收区显示自己发的内容；勾 HEX 显示发 `01 02 03` → 显示 `01 02 03`
5. 鼠标在接收区拖选正文 → 高亮显示；Ctrl+C / Ctrl+Insert / 右键「复制所选」
   可复制到剪贴板；拖到接收区上/下边缘自动滚屏，可跨屏选择屏幕外内容；
   「复制全部文本」仍在；**折行长行**上拖选：高亮与复制内容一致（列含折行
   段偏移、后续行不被折行段错位，十四轮 X1）
6. 右键接收区：「复制含时间戳和收发标记」/「保存含时间戳和收发标记」默认勾选
   （行尾 `●` 标记）；关闭后「复制所选/全部文本」与「保存数据」只出正文，
   再打开后行首 `[时间戳]收←◆` 随行带出——且与「加时间戳和分包显示」是否勾选
   **无关**（显示关着也能带出；选区半途起选的行不带行首注记）
7. 关串口再拔 USB：**不应崩溃**；插回刷新应重现
8. 打开状态拔 USB：出现黄灯“重连中…”提示可接受；等待期按钮转**「取消」**，
   点击应中止轮询并还原（串口被其他程序占用时的打开失败同理）

### 7.3 TCP 回环（两个实例）

1. A：TCP服务端，本地端口 `6000`，侦听——**首次侦听会弹防火墙"允许访问网络"，点允许**
   （点取消 = 侦听失败，不是 bug；前置表里有预置规则命令）
2. B：TCP客户端，`127.0.0.1:6000`，连接
3. 互发各收一句；关 B，A 显示断开；B 重连后收发恢复
4. 100KB 以上连续发，接收区不乱序、不漏
5. **IPv6（纯单栈）**：A 的"本地"IP 选 `::1` 或 `::` 侦听同端口 → IPv4 客户端
   `127.0.0.1` **必须连不上**、`::1` 客户端可连互发（绑哪个族只收哪个族）；
   远程框写 `[::1]` 也应能连（自动剥方括号）；IPv6 侦听同样会弹防火墙提示

### 7.4 UDP 回环

1. A：UDP 本地 `6001` 连接；B：UDP 本地 `6002`、远程 `127.0.0.1:6001` 连接
   ——同样注意首次绑定端口的**防火墙弹窗要点允许**
2. B 发 A 应收到（UDP 无连接，A 状态栏可能仍显示未连接，属正常）
3. Qt5 下 UDP 端口**独占**绑定，同机多实例绑同一端口会失败——不算 bug
4. **IPv6（纯单栈）**：A 的本地 IP 选 `::` 绑定 → 远程 `::1` 的 B 可互发、
   `127.0.0.1` 的 B **发不进来**；远程 IP 填无法解析的串时 A 状态栏应报
   "远程IP无法解析"且只报一次（链路仍绑定：第 1 格保持"已连接"、ERR 灯亮、
   按钮仍为「关闭」），改回合法地址继续发即恢复绿灯

### 7.5 大缓冲 / 长时间观察（32 位重点）

**先关掉两处 USB 电源管理**（否则长时间灌流时系统可能挂起 USB 串口，表现为
静默断连/丢数据，干扰判断——这是串口工具的经典坑，Win7 电源计划默认更保守）：

- 控制面板 → 电源选项 → 更改高级电源设置 → USB 设置 → **USB 选择性暂停 = 已禁用**；
- 设备管理器 → 逐个 USB Root Hub → 属性 → 电源管理 → 取消
  **”允许计算机关闭此设备以节省电源”**。

- [ ] 选 **50M** 档持续灌数据几分钟：界面流畅、不崩、不无限增长
      （任务管理器看 `PyCom32.exe` 提交大小；参考：此前 20M 档实测 250~350MB，
      50M 档应仍显著低于 512M 档的 OOM 线）
- [ ] 接收区能回翻的范围与”保存 → 原始字节(\*.bin)”导出范围**基本一致**
      （行表跟随缓冲裁剪）；要完整留档用”接收数据到文件”
- [ ] 记录结论（多少 MB 数据后提交量多少、是否卡顿/崩溃）。若真机上仍不稳，
      只需调小 `app/core/settings.py` 的 `BUF_CAP_MAX` 一个常量

### 7.6 失败取证

1. **窗口不出来**：`eventvwr.msc` → Windows 日志 → 应用程序，找错误项，记录
   “错误模块名称”（如 `ucrtbase.dll` / `Qt5Core.dll` / `python38.dll`）与异常
   代码——可直接区分缺系统组件、UCRT 问题还是 Qt 问题。
2. **能出窗口但功能不对**：复现最小步骤，带上接收区右键“复制全部文本”的内容。
3. **完全起不来的极端情况**：把产物拷回开发机跑 `python tools\audit_dist_win7.py`
   复核依赖图缺口。
4. 记录目标机 `winver`（是否 SP1）与是否装过 VC++ 运行库。本次产物**自带**
   UCRT（`ucrtbase.dll` 10.0.10240，Win7 SP1+ 官方 app-local 版），不依赖目标机
   装 KB2999226 或 VC++ 运行库。
