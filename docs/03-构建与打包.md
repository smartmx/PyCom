# 03 · 构建与打包

> 基于 2026-10-16 代码状态编写。**共同规则：只打包单文件版，永不产出目录版**
> （2026-10-16 起的既定规则，历史目录版已清理）。单文件 exe 启动时解包到系统
> 临时目录（`sys._MEIPASS`），启动比目录版慢几秒，换来的是一个文件随处拷贝。
>
> 打包前先退出正在运行的 PyCom / PyCom32（产物文件被占用会打包失败或产出旧文件）。

## 1. win64（PyCom）

### 环境

```
pip install -r requirements.txt       # 已锁版本（应用依赖只有 PySide6==6.12.0，无 pyserial）
```

Python 3.13（64 位）。

### 命令

```bash
python main.py                 # 源码运行
python -m pytest tests/        # 99 项单测
tools\build_exe.bat            # 打包 → dist\PyCom.exe（单文件便携版）
```

`build_exe.bat` 内容即 `python -m PyInstaller --noconfirm --clean PyCom.spec`。

### 体积裁剪（PyCom.spec 内置）

单文件版实测 49.7MB → **24.2MB**，靠 spec 里的剔除清单（`_DROP_DLLS`/
`_DROP_DIRS`/`_DROP_FILES`/`_EXCLUDE_MODULES`，各项带注释可移回）：

- 纯 Widgets 应用用不到的 Qt 按需组件：`opengl32sw.dll`（软件 OpenGL，19.7MB）、
  Qt6Qml/Qt6Quick 栈、Qt6Pdf、Qt6VirtualKeyboard、TUIO/虚拟键盘插件、
  Qt 自带翻译 `.qm`（7MB）、`qdirect2d`、networkinformation；
- TLS/加密栈：libcrypto/libssl ×2 + `plugins/tls` + excludes `ssl/_ssl/_hashlib`
  （应用已确认无导入）；
- UCRT（`ucrtbase` + `api-ms-win-crt-*`）：Win10+ 系统自带（Python 3.13 本就
  要求 Win10+），可安全剔除。

底座不可裁：Qt Core/Gui/Widgets + python313.dll。

**约束**：产物要求 Win10+、无 TLS/https 能力（TCP/UDP 调试不受影响）。
若将来引入 QML/OpenGL/Pdf/TLS 或需要 Qt 多语言界面文案，须从剔除清单移回。

## 2. win32（PyCom32）

### 环境（版本有硬上限，不要随意升级）

| 项 | 值 | 原因 |
|---|---|---|
| 解释器 | `D:\Program Files\Python38-x32\python.exe`（3.8.10 **32 位**） | 最后支持 Win7 的组合；非系统默认，**调用须写全路径** |
| GUI | `PySide2==5.15.2.1`（Qt 5.15.2，cp38-win32 wheel） | PySide2 最终版 |
| 测试 | `pytest<8.4` | 8.4 起不支持 Python 3.8 |
| 打包 | `pyinstaller==5.13.2` | 6.10 起不支持 Python 3.8；5.x 对 Qt5 hooks 最稳 |

装依赖：

```
"D:\Program Files\Python38-x32\python.exe" -m pip install -r requirements.txt   # 已锁版本（PySide2 5.15.2.1 / pytest 8.3.5 / pyinstaller 5.13.2——6.x 不兼容本分支）
```

### 命令

```bash
"D:\Program Files\Python38-x32\python.exe" main.py    # 源码运行
"D:\Program Files\Python38-x32\python.exe" -m pytest tests/    # 106 项单测
tools\build_exe.bat                                   # 打包 → dist\PyCom32.exe
```

bat 固定 `set PY=D:\Program Files\Python38-x32\python.exe` 再
`"%PY%" -m PyInstaller --noconfirm --clean PyCom32.spec`——用哪个解释器打包，
产物就是那个位数（历史上曾用 64 位 3.8，现已固定 32 位）。

### spec 三条命门（动打包先看这个）

1. **UCRT 必须随包，且必须用 Win7 那一份**（`vendor/ucrt-x86/`，41 个 dll）。
   Win7 系统不带 UCRT；PyInstaller 默认从**开发机 System32/SysWOW64** 抓
   （Win11 上是 10.0.26100），那份导入 `api-ms-win-core-fibers-l1-1-1` 等
   **Win8+ 才有的 API-Set**——干净 Win7 上 ucrtbase 一加载就失败，程序起不来，
   而开发机（Win10/11）上完全测不出来。spec 现改用微软面向 Win7 SP1+ 的
   app-local 再发行版（Windows SDK 里**不带版本号**的 `Redist\ucrt\DLLs\x86`，
   10.0.10240），已收进 `vendor/ucrt-x86/`（来历见其中 README.md）。
   spec 查找顺序：环境变量 `PYCOM_UCRT_DIR` → `vendor/ucrt-x86/` → SDK 路径；
   **三者皆无则打包直接报错**（宁可失败也不产出 Win7 起不来的包）。
   教训：跨系统版本的 DLL 随包，光看“文件在不在”没用，**要看血统**。
2. **`python3.dll` 必须显式带上**：PySide2 的 QtCore.pyd/shiboken2.pyd 链接
   稳定 ABI 转发库 `python3.dll`（它再转发到 `python38.dll`），PyInstaller 5.x
   默认只收 `python38.dll`，缺它启动即报 "DLL load failed while importing
   QtCore"。spec 经 `sys.base_prefix` 加入（自动适配位数）。
3. **`Qt5Qml.dll` 必须保留**：PySide2 公共支撑库 `pyside2.abi3.dll` **硬链接**
   `Qt5Qml.dll`，按前缀剔 Qml 全家会让 QtCore 导入同样报错。Qt5Qml.dll 自身
   只依赖 Qt5Network（已保留）+ 系统 DLL；Quick 大件（Qt5Quick*）与
   QmlModels/QmlWorkerScript 仍可安全剔除。

### 剔除清单

Qt5 全家未用模块：Quick、QmlModels、QmlWorkerScript、3D、WebEngine、Charts、
多媒体、Sensors、Sql、Test、PrintSupport 等；`opengl32sw.dll`、
`d3dcompiler_47.dll`、OpenSSL（无 TLS 需求）；两个**永远加载不到**的备用平台
插件 `qwebgl.dll`（要 Qt5Quick/Qt5WebSockets）、`qxdgdesktopportal.dll`
（要 Qt5DBus，xdg 是 Linux 的）。

### PyInstaller 5.x 差异注意

- `Analysis` 的 `optimize` 参数是 6.x 才有的，5.13.2 不认，spec 里不能加；
- 5.x 目录版产物没有 `_internal/`（历史信息，目录版已废弃）；
- 单文件版 DLL/UCRT 内嵌在 exe 的压缩归档里，PE 层看不到——UCRT 血统审计
  因此改为**对打包输入**做（见下）。

### 产物审计（打包后必跑）

```bash
cd win32
python tools\audit_dist_win7.py                  # ① 单文件产物：位数 + 引导器导入
python tools\audit_dist_win7.py vendor\ucrt-x86  # ② 随包 UCRT 血统
# 两条都期望结尾：未发现 Win7 兼容性风险项
```

`audit_dist_win7.py`（纯 stdlib）查三件事：① 产物里每个 PE 是否 32 位；
② 每个导入能否在 `产物 + Win7 SP1 系统自带` 里解析；③ 随包 `ucrtbase.dll`/
`api-ms-win-*.dll` 血统——转发目标或自身导入若落在 `kernelbase` 等 Win8+
组件上就报警。**改动打包相关内容后必须重跑。**

定位缺 DLL 的方法论（已固化进该脚本）：用 `struct` 解析 PE 导入表递归对照
dist 清单；`ctypes` 直接加载 dist 的 DLL 会被开发机运行库污染，**结论不可信**。

## 3. 产物一览

| 产物 | 大小 | 位数 | 目标系统 | 状态 |
|---|---|---|---|---|
| `win64/dist/PyCom.exe` | ≈24MB | x64 | Win10+ | 已验证可启动（开发机） |
| `win32/dist/PyCom32.exe` | ≈20MB | x86（machine=0x014c） | Win7 SP1+（32/64 位系统） | 开发机（Win11 WoW64）启动冒烟通过；**真机 Win7 验收待做** |

> **发布提示（杀软误报）**：PyInstaller 单文件版的自解压结构是杀软启发式的
> 重点误报对象（恶意软件常被加壳分发，见 [pyinstaller #6754](https://github.com/pyinstaller/pyinstaller/issues/6754)），
> 国内常见安全软件与老杀软（Win7 上尤其）可能报毒。属误报，缓解手段按效力排序：
> 代码签名证书 > 向杀软厂商提交误报申诉 > 用户手动加白名单。发布说明里建议附上这句。

> 源码工程为本体；两分支各自的 `dist/<产物>`（`win64/dist/PyCom.exe`、
> `win32/dist/PyCom32.exe`）均为最近一次构建的交付物（重新打包覆盖生成）。
> `build/`、运行期 `pycom*.json`、`PyCom-Log-*.txt` 等均为生成物，
> 发布/备份时排除。产物与配置/日志的关系：exe 落地目录旁会生成各自配置文件
> （PyCom→`pycom.json`、PyCom32→`pycom32.json`，独立命名互不覆盖）与
> `PyCom-Log-*.txt`（见 [02-架构与代码导读.md](02-架构与代码导读.md) 第 9 节）。
