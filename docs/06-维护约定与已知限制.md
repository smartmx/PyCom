## 1. 双分支维护约定

1. **功能只在 win64/ 主线开发**；win32/ 是“老机器专用版”，只同步修复，不开新功能。
2. 主线改完代码**先跑根目录 `sync_check.py`**：`[=]` 的文件两分支应保持一致，
   `[!]` 的差异块逐个判断要不要手工移植（移植时按
   [04-Win7-32位适配说明.md](04-Win7-32位适配说明.md) 的 Qt5 规则改写，例如
   菜单动作 lambda 用 `lambda _=False, ...:` 形态）。移植后重跑确认差异收敛回
   有意差异清单（见 04 第 9 节）。
3. 改完 win64 代码要**重启 GUI 调试界面供人工检查**：先按窗口标题停掉旧进程，
   再以持久后台方式启动 `python main.py`（普通命令行的 `&` 子进程会随命令
   结束退出），确认窗口弹出。
4. 两分支各自跑各自的测试（命令见 [05-测试与验收.md](05-测试与验收.md) 第 2 节）；
   win32 的一切 pytest/pip 调用必须写 32 位解释器**全路径**。

## 2. 动代码前的坑清单（速查）

| # | 坑 | 一句话规则 |
|---|---|---|
| 1 | 线程模型 | 全部 socket/serial 主线程信号槽，**不开线程**；Qt 槽里不得抛异常穿透（参考 `_shrink_on_oom`） |
| 2 | 性能路径 | 字节→环形缓冲→增量行→只画可视区；**禁止改成整段重绘/全量刷新** |
| 3 | 编码入口 | 收/发/终端/日志全走 `_current_encoding()` 单入口；勿改回下拉框 |
| 4 | 空行语义 | 包尾换行不留空游标；方向/模式切换伪影用 `_close_open(keep_empty=...)` 丢 |
| 5 | 路径 | 用户可见文件一律 `app/paths.py base_dir()`（打包版=exe 目录） |
| 6 | 转存游标 | 清屏必须发 `RxView.cleared`，否则转存日志重字/漏字 |
| 7 | terminal.py 原始字节 | win64 版该文件含隐形 ESC/BS 原始字节，编辑前 `grep -c $'\x1b'` 核对（应为 10）；win32 版是显式转义 |
| 8 | 打包 | 只出单文件版；打包前退出运行中的程序；win32 打包后必跑 `audit_dist_win7.py` 两条命令 |
| 9 | 任务栏图标 | `SetCurrentProcessExplicitAppUserModelID` 必须在 QApplication 之前 |
| 10 | 窗口几何 | 配置里的宽高要钳制到屏幕；外框修正在 `showEvent` 后做 |
| 11 | 串口禁用 waitFor* | QSerialPort 事件驱动模式下**不得调用 `waitForReadyRead` 等阻塞等待**——Qt5 每次超时都会给端口置 TimeoutError 并发 errorOccurred（实测 CH343 一次不落），错误状态被反复污染；接收只 `readAll()`，见 `serial_link._on_rx` 注释 |
| 12 | 数据含 NUL 会让绘制崩 | 0x00 字节解成 U+0000 后 PySide2 `drawText` 抛 embedded null character，接收视图每帧中断（界面假死）；`display._emit_text` 已统一剥离，接收链路新增绘制代码时注意 |
| 13 | 新增 tools 脚本的输出守卫 | **固定模板**：脚本开头对 `sys.stdout/sys.stderr` 调 `reconfigure(errors="replace")`（`AttributeError` 吞掉）——中文 GBK 控制台打印含非 GBK 字符（▶/● 等）会直接崩溃，已两度复发（audit_dist_win7、sync_check），勿第三次 |

## 3. 文件位置（运行期）

| 文件 | 位置 | 说明 |
|---|---|---|
| `pycom.json`（win64）/ `pycom32.json`（win32） | exe（或 main.py）同目录 | 全部参数；“保存参数”或关窗时写入。**2026-10-16 起 win32 独立命名**，两个产物拷进同一目录互不覆盖 |
| `PyCom-Log-YYYYMMDD_HHMMSS.txt` | 同目录 | 接收转存（勾选即建，每次勾选新建） |
| `received.txt` / `received.bin` | 同目录 | 手动“保存”（文本/原始字节） |
| `assets/` | 项目内 | svg 运行期图标 + ico 打包图标（打包后无需随行） |

## 4. 已知限制

- ADD/XOR/ADD16 校验按累加/异或通行惯例实现，原版规格未公开；如有出入改
  `app/core/checksum.py`。
- 长行折行无横向滚动（鼠标选择复制已实现：拖选 + Ctrl+C/Ctrl+Insert + 右键，
  边界自动滚屏；带不带时间戳/收发标记由右键两项决定，见 docs/01 §5.2）。
- 超长逻辑行折行后的**显示行**未纳入垂直滚动模型：滚动条按逻辑行计数，单行
  折行段很多时滚到底也可能看不到最后几段（尾部被推到视口下方）。命中/选择
  映射已与绘制几何同源（折行段计入列、行号按上方实际占用的视觉行回推，
  2026-10-19 十四轮 X1 修复，折行段也不再与后续行叠画）；彻底解是按"显示行"
  建模（`wrap_ref/` 方案 A：cells 缓存 + RowIndex 前缀和，滚动/绘制/命中统一
  坐标系）。
- GB2312 列表项与 GBK 解码结果相同（超集关系），仅为习惯保留。
- 切换显示编码只影响后续数据，已显示内容不重算（设计如此）。
- 接收区搜索在 GUI 线程同步执行：500K 行单次全量扫描约 170ms（2026-10-15
  实测），已用 250ms 输入防抖 + 500ms 数据重算节流降低频率；高吞吐下要完全
  流畅需增量索引或移出主线程。
- 两个 ISP 烧写器与数据波形示波器**确定不做**（2026-10-17 定版决策，见第 5 节）。
- win32：Qt5/32 位带来的边界（UDP 独占绑定、无暗色标题栏、缓冲上限 50M）
  见 [04-Win7-32位适配说明.md](04-Win7-32位适配说明.md) 第 6/8 节。
