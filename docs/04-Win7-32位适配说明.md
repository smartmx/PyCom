# 04 · Win7 / 32 位分支适配说明

> `win32/`（应用名 **PyCom32**）是 `win64/`（PyCom）的 Win7 兼容回迁分支。
> 本文整合自该分支的回迁台账，按 2026-10-16 代码状态编写；打包细节在
> [03-构建与打包.md](03-构建与打包.md)，验收步骤在 [05-测试与验收.md](05-测试与验收.md)。

## 1. 分支定位与维护模式

- `win32/` 是主线整树副本 + 一层明确的 Qt5/32 位适配，**主线代码零改动**；
- 后续主线变更需**手工同步**到本分支：先跑本目录根的 `sync_check.py`
  （见第 9 节）判断哪些是功能差异，移植后重跑确认收敛；
- 维护模式：主线收新特性，win32 仅作“老机器专用版”每轮同步修复，**不开新功能**；
- 2026-10-16 起本分支整体为 **32 位**（产物一个 `PyCom32.exe` 通吃 Win7 32/64
  位系统），版本号与主线同步（V0.0.3，`app/version.py`）。

## 2. 为什么必须回迁（两层独立原因）

1. Python 3.9+ 官方不支持 Win7（3.13 要求 Win10+）；
2. Qt6 不支持 Win7。

所以选定 **Python 3.8.10 32 位 + PySide2 5.15.2.1（Qt 5.15.2）**——各自
支持 Win7 的最后版本。运行时已冻结：Python 3.8 已 EOL、PySide2 5.15.2.1 为
最终版，这两个版本不会再变。

## 3. 环境

| 项 | 值 |
|---|---|
| 解释器 | `D:\Program Files\Python38-x32\python.exe`（3.8.10 **32 位**；目录名带 `-x32`，非系统默认，调用须写全路径） |
| GUI | `PySide2==5.15.2.1` |
| 测试 | `pytest<8.4` |
| 打包 | `pyinstaller==6.22.2`（2026-10-24 由 5.13.2 升级与主线同版，目录版随之获得 exe + `_internal/` 布局；官方支持面 Win8+、引导仍按 Win7 特性级编译，升级后已 Win7 32 位真机复验启动正常，见 docs/03 §2 与 docs/05 §7.7） |

64 位解释器 `D:\Program Files\Python38` 仍保留（如需回退改 bat 的 `set PY=` 即可，
但一般不要——当前 32 位是超集）。

## 4. 代码变更清单（相对 win64/ 主线）

### 4.1 导入与模块归属
- 全部 `from PySide6.*` → `from PySide2.*`（13 个源文件 + 测试 + tools）。
- **QActionGroup、QShortcut 从 QtGui 移回 QtWidgets**（Qt6 才挪到 QtGui）。

### 4.2 方法名
- `exec()` → `exec_()`（PySide2 无 `exec` 别名）：入口 `app.exec_()`、字体对话框、
  接收区右键菜单三处。

### 4.3 枚举写法
Qt6 完全限定枚举 → Qt5/Qt6 通用的**简写**（枚举数值两代一致）：
`QEvent.Type.Wheel`→`QEvent.Wheel`、`Qt.GlobalColor.transparent`→`Qt.transparent`、
`Qt.Key.Key_*`→`Qt.Key_*`、`QComboBox.SizeAdjustPolicy.*`、`QFrame.Shape/Shadow.*`、
`QAbstractItemView.*`、`QNetworkInterface.*`、`QAbstractSocket.*` 等（约 20 处）。
`sync_check.py` 会把这些归一化掉，不报差异。

### 4.4 明暗主题
`styleHints().setColorScheme()` 是 Qt 6.5+ API：Qt5 下由原有
`try/except AttributeError` 兜底自动变 no-op（保留）。Qt5 的明暗完全由应用自身
控制：QSS + 显式 QPalette + DWM 标题栏直调（照搬，未改）。
**对话框标题栏跟随深色（2026-10-20 新增，主线靠 Qt6.5+ setColorScheme 自动跟随、
Qt5 缺失需自做）**：应用级**单例**事件过滤器（`_DialogDarkFilter`，弱引用当前
主窗口——若每窗口自装全局过滤器，QApplication 过滤器列表会强持其 Python 包装，
旧窗口永不释放且事件分派 O(N²)，实测全量跑拖慢 10 倍）对**顶层对话框**（QDialog
系，含 QMessageBox/QInputDialog/QFileDialog）的 Show 事件统一调 DWM 置暗（复用
主窗口同一对属性 20/19）；Win10 1809+ 生效，**Win7 无此 DWM 属性、调用自动忽略
——标题栏保持系统浅色属系统限制**（深色内容区不受影响）。

**多条发送表格深色手绘（2026-10-20 新增，同根因：Qt5 原生样式不吃深色调色板）**：
`_SendBtnDelegate`（点击发送按钮）与 `_HexCheckDelegate`（HEX 勾选框）原本经
`QApplication.style()` 原生直绘——windowsvista 样式画出的按钮恒浅灰、未勾选
指示器恒白块，与主题无关；表头角落按钮（QTableCornerButton::section）同理白块。
修复：深色下两委托改按 `theme.vars("dark")`（与 QSS 同源颜色）手绘按钮/勾选框
（勾选画对勾），QSS 显式样式化角落按钮；**浅色仍走原生**（观感=系统按钮），
以 `QPalette.Window` 亮度 <100 判定明暗（`_ui_is_dark()`）。主线 win64 靠
setColorScheme 让 windows11 原生样式自动跟随深色，无需此处理——属有意差异。

### 4.5 高分屏（Qt5 需显式开启）
`main.py` 在创建 QApplication 之前：
```python
QApplication.setAttribute(Qt.AA_EnableHighDpiScaling, True)      # Qt6 默认开启
QApplication.setAttribute(Qt.AA_UseHighDpiPixmaps, True)
QApplication.setHighDpiScaleFactorRoundingPolicy(...PassThrough)  # 对齐 Qt6 默认
```

### 4.6 terminal.py 转义重写（语义不变）
win64 源码里 ANSI 序列的 ESC(0x1b)/BS(0x08) 是**原始控制字节**（编辑工具易丢）。
win32 版改为显式 `b"\x1b[A"`、`b"\x08"` 转义，运行语义完全相同
（也见 [02-架构与代码导读.md](02-架构与代码导读.md) 第 8 节第 10 条）。

### 4.7 测试适配与守卫
- `QTest.qWait` 在 PySide2 不存在：文件头部加了事件循环轮询垫片（`hasattr`
  判断，两版本通用）；
- **静态守卫** `test_menu_triggered_slots_accept_zero_args`：扫 `app/` 里所有
  `triggered.connect(...)`，lambda 首参无默认值/具名槽有必填参数即失败并指出
  `文件:行号`（防第 5.1 条坑复发；`QActionGroup.triggered` 这类带 action 参数的
  信号在连接处标 `PYCOM-OK-TRIGGERED-ARG` 豁免）；
- 菜单真实触发回归：模式切换、缓冲上限、编码、发送文件延时菜单逐个 `trigger()`。

### 4.8 文案
“关于”对话框技术栈为 PySide2，并注明“系统要求：Windows 7 SP1 及以上；32 位
程序”；窗口标题/产物名/AppUserModelID 均用 PyCom32。

## 5. 运行期修复的四个 Qt5/PySide2 行为坑（真平台实测发现）

1. **PySide2 的 `QAction.triggered` 不传参**（PySide6 会把 checked 布尔传给槽）。
   带必选参数的 lambda（如 `lambda c, m=mode: ...`）在 PySide2 下触发即抛
   TypeError，**槽函数静默不执行**——症状是“通讯端口菜单点 TCP/UDP 切不过去”、
   “显示缓冲上限菜单点了没反应”。修复为 `lambda _=False, m=mode:` 形态
   （PySide2/6 通吃），win32 新菜单动作一律用此形态。排查手段：真实平台跑源码
   看 stderr；offscreen 测试不覆盖菜单点击路径（现已用 4.7 的守卫+触发用例补上）。
2. **Qt5 的 QSS 定制菜单：可勾选条目的文字被 indicator 顶右错位**。只要
   `QMenu::indicator` 有尺寸，Qt5 就把**可勾选条目**的文字缩进一个 indicator 宽度
   （普通条目不缩进）。真机 Win7 分数缩放（125%/150%）下勾号图形全系列不可用：
   手绘多边形路径缺笔乱码、✓ 字符位图（Segoe UI Symbol 13/14px 单描/双描）发虚、
   **系统原生 indicator 勾号也发虚**（Qt5 连主题位图都被拉伸）、给不可勾选条目垫
   透明图标对齐还会把弹出菜单**高度算短、底边被裁**（Win11 无此问题，纯 Qt5
   缺陷）。行首标记（ASCII `*`/全角 `＊`/`●`/`○`/`◇`）在真机逐一试过：
   图形全系列发虚或缺笔，文字字符又因 ● 在菜单字体（微软雅黑）里是窄字符、
   与全角空格不等宽而无法前置对齐。**2026-10-16 终版定稿：勾选标记 =
   行尾实心圆 `●`**——条目文本前缀完全不动（汉字天然对齐），列对齐用
   Qt 菜单自带的**制表符右对齐机制**（`文字\t　●`，快捷键提示即此布局），
   所有标记由 Qt 排到同一右边界天然成列；标记前垫全角空格（间距 ≥ 两个
   空格）。标记由 `MainWindow._refresh_menu_markers` 在每次弹出前按勾选态
   写进/撤出文本（幂等）；带 QAction 快捷键的条目不勾选、互不影响；
   勾选态不铺底色。守卫 test_menu_text_marker（条目无图标、QSS 归零
   indicator、弹出前刷新行尾标记、未勾选/不可勾选条目无标记）。
   接收区右键菜单的两项注记开关（复制/保存含时间戳和收发标记）同用该约定：
   菜单每次弹出重建，`RxView._build_menu` 直接按状态写行尾 `●`（两分支同一
   实现，见 docs/01 §5.2；测试 test_rxview_menu_toggles_anno 守卫）。
   核对图 `win32/docs/menu_checkmark_*.png`、`menu_align_mixed_*.png` 为
   **早期图标列方案**所摄（2026-10-16 09:33），终版行尾 ● 以
   test_menu_text_marker 为准。
3. **不能靠 `QAction.menu()` 遍历菜单树**：返回的 Python 包装器一旦被 GC，会把
   背后的 `QMenu` C++ 对象一起删掉（随后报 "Internal C++ object already
   deleted"）。取菜单用 `QMenuBar/窗口.findChildren(QMenu)`（`_build_menus` 末尾
   收集 `self._menu_list` 即此因）。
4. **事件驱动模式下调用 `waitForReadyRead` 等阻塞等待会污染端口错误状态**
   （2026-10-16 实测）：Qt5 的 Windows 后端里每次 `waitForReadyRead(0)` 超时
   都会给端口置 **TimeoutError** 并发 `errorOccurred`（在真实 CH343 上逐次
   实测，一次不落）。原代码在 `_on_rx` 里用 `while waitForReadyRead(0)` 排空，
   等于每个数据包都污染一次；已改为 `_on_rx` 只 `readAll()`（后续数据会再次
   触发 readyRead，无需排空）；两分支同步修改保持一致。**给串口加任何
   “同步等待”类代码前先读这条。** 另：PySide2 里 `QSerialPort.error` 绑定的
   是（过时的）信号而不是 getter，探测错误状态只能用 `errorOccurred` 信号 +
   `errorString()`。
5. **设备数据含 0x00 字节会让接收视图每帧绘制中断（界面假死）**
   （2026-10-16 用户报“打开串口后界面一直显示不正常、滚轮才恢复”，实锤修复）：
   GBK 等编码把 0x00 解成 U+0000，而 **PySide2 的 `QPainter.drawText` 不接受
   内嵌空字符的字符串**（抛 `ValueError: embedded null character`，PySide6 已
   改用带长度转换、不受影响），paintEvent 每帧都抛异常中断 → 视图不重绘；
   滚轮把含 NUL 的行滚出视口后绘制才走完。另注意：CH34x 类驱动在端口**关闭
   期间会缓存接收数据**，打开瞬间一次吐出（实测 334 字节），这段历史数据是
   同一个包的续行、不带时间戳前缀（符合分包语义，不是 bug）。
   修复：`display._emit_text` 入口统一剥离 NUL，行表/渲染/复制/日志一致；
   两分支同步。**往接收链路里加任何“str→Qt 绘制”代码前先想 NUL。**

## 6. 32 位内存边界与缓冲定档

32 位进程用户地址空间只有 2GB，主线的 512M 缓冲档到这里站不住。
`tools/mem_probe.py`（把真实接收链路灌满，测提交量/工作集）实测：

| 档位 | 实际灌入 | 提交量 | 峰值提交 | 结果 |
|---|---|---|---|---|
| 128M | 128MB | 234MB | 356MB | 正常（行表 45.7 万行） |
| 256M | 256MB | 595MB | 842MB | 正常 |
| 512M | 310MB 即失败 | 989MB | 1267MB | **MemoryError** |

（32 位 Python 3.8 + PySide2，offscreen；内存构成 ≈ 缓冲 + 行表(上限 50 万行)
+ Qt 自身约 120MB）

**定档：默认 5M 不变、上限 20M → 50M**（2026-10-16 三轮定档：128M/10M → 50M/5M → 20M/5M；2026-10-20 应用户要求放宽到 50M——历史实测 128M/256M 档正常，50M 远离 512M 档的 OOM 线，且有下述自动降档兜底）。
据此：

1. 口径常量 `settings.py` 的 `BUF_CAP_DEFAULT=5MB` / `BUF_CAP_MAX=50MB`（最小档 500K，已删的 200K 档老配置收敛到此），配置归一化、原版 ini 导入（N1067 写 512M 也被钳到 50M）、菜单档位全部以此为界；
   `mainwindow.py` 的 `_MAX_BUF` 直接引用 `BUF_CAP_MAX`，避免两处漂移；
2. `MainWindow._clamp_cap()` 开窗兜底（配置被人手改大也不越界）并同步菜单勾选态；
3. **内存耗尽降级** `_on_rx` / `_shrink_on_oom`：`buf.append` 或 `builder.feed`
   抛 `MemoryError` 时把上限减半、清出空间重试一次；仍失败只丢**这一包**并在
   状态栏提示“内存不足”，绝不把 MemoryError 抛回 Qt 槽；
4. 旧配置迁移：`pycom.json` 里的历史默认值已随定档更新为最终默认值。

裁剪机制本身（两个上限共用、按包粒度、日志游标保护）见
[02-架构与代码导读.md](02-架构与代码导读.md) 第 7 节。

## 8. 已知 Qt5 行为差异（真机回归时关注）

1. **UDP bind 默认标志不同**：Qt5 `bind(addr, port)` 默认 `DontShareAddress`
   （独占），Qt6 默认可复用。同机多进程绑同一 UDP 端口的表现会不同；常规单实例
   无影响（真机清单里也标注了这条“不算 bug”）。
2. **深色标题栏**：DWM 沉浸式暗色（属性 19/20）仅 Win10 1809+ 有效；Win7 上调用
   失败被现有 `except` 静默吞掉，标题栏保持系统样式（Win7 本无暗色标题栏），
   窗口内部深色不受影响。
3. **系统明暗联动**：Qt6 的 setColorScheme 会影响部分原生元素；Qt5 完全由应用
   QSS/调色板控制——表现与主线一致（主线也是显式设色板）。
4. 代码里用的是 `QMenu.exec_` 等旧名；若未来抄回主线注意 Qt6 两种名字都认。

## 9. sync_check.py（主线↔分支同步核对工具）

位于 Develop 根目录，比对 `win64/` ↔ `win32/` 的 22 个共同文件。它把已知的
Qt5 适配改写**归一化掉**（PySide6/2→PySideX、`exec`/`exec_`→RUN、Qt6 完全限定
枚举→简写），并剥离全部注释，只报**真正需要手工移植的功能差异**。

```bash
python sync_check.py        # 列出残留差异块（含两侧代码片段）
python sync_check.py -q     # 只列文件级摘要
```

截至 2026-10-24，9 个文件存在**有意**的实质差异（属正常，勿“修平”）：
`settings.py`（缓冲档位 10M/100M vs 5M/50M）、`terminal.py`（转义写法）、
`mainwindow.py`（Qt5 菜单勾选标记行尾 ●/triggered 形态/32 位钳制/对话框与
扩展小窗标题栏事件过滤（DWM 逐窗置暗，Qt5 无 setColorScheme）/多条发送表格
深色手绘委托等）、`theme.py`（QMenu indicator 归零/
QTableCornerButton 角落着色/vars() 取色访问器）、`main.py`（HighDpi 属性）、
两个测试文件（Qt5 守卫用例）、`make_ico.py`（枚举写法）、`rxview.py`（鼠标坐标
API：Qt5 `localPos()` / Qt6 `position()`）。其余 13 个文件应保持 `[=]`。
