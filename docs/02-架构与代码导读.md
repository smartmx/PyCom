# 02 · 架构与代码导读

> 基于 2026-10-16 代码状态编写。win64/ 与 win32/ 结构完全一致，
> 差异（Qt5 适配、32 位专属）见 [04-Win7-32位适配说明.md](04-Win7-32位适配说明.md)；
> 本文描述共同架构。**改代码前先读第 8 节的坑清单。**

## 1. 总体架构

两层结构，单向依赖：`app/ui/` → `app/core/`（纯逻辑层不知道 Qt 界面的存在，
可直接单测）。入口 `main.py` 负责主题与配置加载。

```
main.py ──> app/ui/mainwindow.py（主窗口，组装全部界面与菜单）
                │ 信号槽
                ├──> app/core/serial_link.py   QSerialPort 封装
                ├──> app/core/net_link.py      TcpClient / TcpServer / Udp
                ├──> app/core/display.py       LineBuilder 行格式化
                ├──> app/core/rxbuf.py         环形字节缓冲
                └──> app/ui/rxview.py          自绘接收视图
```

## 2. 目录结构（win64/，win32/ 同构）

```
win64/
├─ main.py                 入口：AppUserModelID → QApplication → 主题/配置加载
├─ PyCom.spec              PyInstaller 打包配置（单文件版）
├─ pycom.json              运行配置（程序自动读写，与 main.py 同目录）
├─ app/
│  ├─ version.py           APP_VERSION（V0.0.4，唯一版本号来源）
│  ├─ paths.py             base_dir()：用户可见文件的根目录
│  ├─ core/                纯逻辑与连接层（可单测，见 §3）
│  └─ ui/                  界面层（见 §4）
├─ tests/                  test_core.py + test_gui_logic.py（win64 125 项 / win32 134 项）
├─ tools/build_exe.bat     打包脚本；make_ico.py（svg→ico）
├─ assets/                 pycom-icon.svg + pycom.ico
└─ docs/                   界面截图与原版比对图
```

win32/ 额外多出：`vendor/ucrt-x86/`（Win7 专用 UCRT 随包 DLL）、
`tools/audit_dist_win7.py`（产物 PE 审计）、`tools/mem_probe.py`（32 位内存实测）、
spec 文件名为 `PyCom32.spec`。

## 3. app/core/ 模块明细

| 模块 | 职责 |
|---|---|
| `rxbuf.py` | 环形字节缓冲：上限可配（`settings.BUF_CAP_*` 为唯一口径），溢出丢最旧；`start_abs` 记录丢弃水位 |
| `display.py` | **LineBuilder 增量行格式化**：HEX/ASCII、时间戳分包（前缀随行记录，显示/复制/保存各自决定是否带出）、增量编码解码（跨包多字节不乱码）、跨包续行、空行语义、`trim_before_abs` 行表裁剪；`lines` 只含已收尾行，另有 50 万行硬上限（`max_lines`） |
| `checksum.py` | 7 种校验（`CHECKSUM_KINDS`）+ 字节范围；`checksum_appendix(kind, body)` 产出追加字节 |
| `hexutil.py` | 宽松 HEX 文本解析（空格/逗号/0x 前缀混排） |
| `link.py` | Link 抽象基类：`rx` / `tx_done` / `state_changed` 信号 |
| `serial_link.py` | QSerialPort 封装 + 拔出检测 + 自动重连；端口枚举 |
| `net_link.py` | TcpClient / TcpServer(多客户端) / Udp + 自动重连；网卡枚举 |
| `multisend.py` | 多条模型（QAbstractTableModel，上限 100 行）+ 循环调度（顺序 0=跳过） |
| `txfile.py` | 发送文件 256B 分块 + 五档延时 + 停止 |
| `terminal.py` | 终端按键→字节映射（含方向键 ANSI 序列）、0D 补 0A、回车行模式回显 |
| `settings.py` | JSON 持久化（原子写、嵌套归一化、越界钳制）+ 原版 sscom51.ini 导入器 + `BUF_CAP_*` / `ENCODINGS` 口径常量 |

## 5. 线程模型（硬约束）

所有 QSerialPort / QTcpSocket / QUdpSocket 都在**主线程事件驱动 + 信号槽**，
不另开线程。新增连接类功能必须遵守——收发路径直接跑在 Qt 槽里，
win32 的内存降级（`_shrink_on_oom`，仅 32 位分支定义；64 位无此路径）也因此
必须兜住异常、不能把 MemoryError 抛回槽。

## 6. 接收显示性能路径（不要改成全量刷新）

```
原始字节 ──> rxbuf 环形缓冲（字节上限）
                │ feed（增量，final=False 解码器）
                ▼
        LineBuilder 行记录表（行数上限 50 万）
                │ 只取可视区行
                ▼
            rxview 绘制（30fps 合并刷新；未收尾行跨包续接）
```

大缓冲不卡的关键就在“增量”二字：字节增量入缓冲、行增量生成、绘制只画可视区。
**任何“整段重绘/全量刷新”式改法都是倒退。**

## 7. 缓冲与行表（两个上限共用一套裁剪）

**口径常量**（`app/core/settings.py`，两分支数值不同，菜单档位/配置归一化/
原版 ini 导入全部以此为界）：

| 常量 | win64 | win32 |
|---|---|---|
| `BUF_CAP_DEFAULT` | 10MB | 5MB |
| `BUF_CAP_MIN` | 500K | 500K（200K 档已删，老配置收敛到此） |
| `BUF_CAP_MAX` | 100MB | 50MB（2026-10-20 放宽，来历见 docs/04 第 6 节） |

**上限管什么**：`RxBuffer` 存**原始字节**（决定 `保存 *.bin` 能导出多少 + 内存占用），
而**行表跟随它的保留范围裁剪**——缓冲丢最旧字节时，`_on_rx` 调用
`builder.trim_before_abs(buf.start_abs, keep_after_line=日志游标)`
（封装在 `MainWindow._trim_lines_to_buf()`），把整包都落在丢弃区间里的行一起丢掉。
于是：

- **接收区能回看的内容 ≈ 保存 \*.bin 能导出的内容**，不会“屏幕上有、导出没有”；
- 上限同时决定“回看深度”和“*.bin 容量”——调小会让屏幕历史跟着变短
  （win64：5M ≈ 15 万行短文本 / 32 万行 HEX；上限放大到几十 M 以上时，
  通常是行表硬顶先到）；
- 行表另有 **50 万行硬上限**（`display.py max_lines`，内存预算 ≈100MB）作为
  第二判据，两个判据先到先裁；
- **裁剪粒度是“包”**：行记录的 `start_abs` 按**包**记录（同一包内所有行相同），
  跨界的那一包整包保留——误差上界是一包的数据量（通常 ≤ 空闲超时那一小段）；
  最后一包永不裁（结束位置未知）；
- 打开“接收数据到文件”时传**日志游标**：尚未写盘的行不许裁（`keep_after_line`
  = `_rx_log_written`，勿用 `nl_done`），既防漏行也不会把整张表钉死；
- 运行中调档（`_set_buffer_cap`）与内存降级（`_shrink_on_oom`，仅 win32）都**立即**同步裁行。

想长时间完整留档用“接收数据到文件”（逐行即时落盘，不受两个上限影响）。

win32 的 50M 档放宽依据与内存实测数据见 [04-Win7-32位适配说明.md](04-Win7-32位适配说明.md) 第 6 节。

## 8. 关键约定与坑（改动前必读）

1. **编码统一入口** `MainWindow._current_encoding()`：编码由菜单栏“编码”菜单
   选择（12 预置互斥 + “自定义编码…”对话框），当前值存 `self._encoding`，
   入口直接返回。收/发/终端按键/日志全部走这一个入口。
   历史：早期为可编辑下拉框，因手输后 `currentData()` 返回旧值等问题改为菜单——
   **不要再改回下拉框**。
2. **空行语义**（display.py）：数据里真实连续换行→保留空行；**包尾换行不留空
   游标**（`_emit_text` 对末尾空段直接跳过）；方向/模式切换的伪影丢弃用
   `_close_open(keep_empty=...)` 区分。做错的表现是“加时间戳和分包显示”
   整体失效（只有第一个包有戳）。
3. **路径**：一切用户可见文件（pycom.json、日志、导出）经 `app/paths.py
   base_dir()`——打包版 `sys.frozen` 判定取 exe 目录，否则配置会落进解包
   临时目录（单文件版）或 `_internal`（目录版）。
4. **多字节跨包**：编码用增量解码器（`final=False` 自动缓存不完整序列）；
   切换编码重建解码器，已显示内容不重算。
5. **PySide6/Qt 通用坑**：`bind/listen` 必须位置参数；UDP 自发自收可当回环
   测试；离屏（offscreen）平台无字体，**界面验证必须真实平台**。
6. **接收转存**：勾选即生效、无文件对话框；100ms poll 只写新收尾行
   （`builder.lines` 天然只含已完成行）；`RxView.cleared` 信号负责清屏后
   重置写入游标——新增清屏路径必须发这个信号，否则日志会重字或漏字。
7. **Windows 任务栏图标**：必须在创建 QApplication 之前调用
   `SetCurrentProcessExplicitAppUserModelID`（main.py `_set_windows_app_id`），
   否则任务栏按 python.exe 分组。
8. **窗口几何钳制**：加载 `win_w/win_h` 后钳制到 `primaryScreen().availableGeometry()`；
   含标题栏的外框修正放在 `showEvent` 首次显示后做（显示前 `frameGeometry()`
   是估计值）。否则大配置值会把状态栏/底部面板顶出屏幕。
9. **RxView 正文顶格**：正文一律从行首绘制，时间戳仅作为包首行的**行内前缀**
   （灰色）。勿引入“固定时间戳前缀列”（会让无戳行整体缩进）。
10. **terminal.py 的原始控制字节**（win64 特有）：源码 ANSI 序列含**原始
    ESC(0x1b)/BS(0x08) 字节**，部分编辑器/工具会无声丢掉。编辑该文件前先
    `grep -c $'\x1b' app/core/terminal.py`（应为 10）核对；win32 版已改显式
    `\x1b`/`\x08` 转义（语义相同）。

## 9. 配置持久化

- 配置文件与 exe（或 main.py）同目录，win64 为 `pycom.json`、win32 为
  `pycom32.json`（2026-10-16 起独立命名，两个产物拷进同一目录互不覆盖）；
  “保存参数”或关窗时写入（原子写）；启动时读取并做越界钳制/嵌套归一化
  （配置被人手改坏也不会崩）。
- 原版 `sscom51.ini` 导入（仅导入，导出已按需求删除）：键名 N1xx
  （N1..N99 多条内容、N101.. 头、N1053.. 参数），**键值带前导逗号需剥离**
  （如 `N1067=,134217728`）；越界值按本分支 `BUF_CAP_*` 收敛。
